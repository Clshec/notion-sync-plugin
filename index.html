نسخة تجريبية — المزامنة التلقائية مغلقة

Notion هو المكان الأساسي للتخطيط، وSuper Productivity للتنفيذ. بمجرد ربط التوكن بالقواعد المشتركة الصحيحة تبدأ مزامنة المهام الجديدة تلقائيًا؛ لا تُرحّل المهام القديمة دفعة واحدة.

اربط Notion بخطوة واحدة

في Notion امنح التكامل الوصول إلى قواعد «اللوح» و«العادات» و«المستويات العليا والفرعية»، ثم الصق مفتاح API هنا. ستُكتشف القواعد والحقول تلقائيًا وتبدأ المزامنة بلا أي إعداد آخر.

لم يتم اختبار اتصال Notion بعد. المزامنة التلقائية والكتابة مغلقتان.

  EXPERIMENTAL · CORE SYNC STARTS AFTER TOKEN CONNECTION
  
Notion plans; Super Productivity executes. Verified one-token connection enables core new-task/project sync and linked task planning/time on this device. These advanced controls are for diagnostics or separately scoped legacy habit/Pomodoro features, not steps ordinary users need to complete. Notion databases and properties are never created by discovery. Complete rich-text body sync and cross-device simultaneous writers are not yet accepted.





  
1. Connect your existing Notion data sources

  

    
    
    
    
  

  
Use the data source ID, not the parent database ID. The token is stored per device through the Super Productivity local secret API, never in synced settings. Super Productivity's local secret storage is not hardware-encrypted. Your Notion integration must be shared with the selected existing data sources.

  

    
    
  





  
2. Map properties already present in Notion

  
Use existing property names (or Notion property IDs). Click Pin task property IDs before renaming fields to English: the plugin saves stable IDs, without changing any Notion schema or pages.

4. Optional manual import into Super Productivity

  
This action writes only to Super Productivity, never to Notion. Select individual rows in the preview above. Bundles import before subtasks, and a subtask is skipped rather than detached when its parent is missing. This is a testing feature, not automatic sync.

  
  
  

  





  
4b. Notion planning → already-linked SP tasks (manual, opt-in)

  
Notion remains the planner. After changing task titles, planned work time or execution date in your existing Notion board, refresh the preview above and select the tasks to update. This changes only the selected SP task's title, estimated work time and execution date. It never overwrites tracked time, completed status, notes, projects, subtasks or habit records. Empty Notion dates/estimates are not treated as deletion requests.

  
Only currently active, individually linked, non-recurring, unfinished SP tasks are eligible. If either side has changed since review, the task is skipped. Nothing updates automatically on either device; SuperSync remains responsible for SP cross-device synchronization.

  

  

  
  

  





  
4c. Experimental automatic Notion → SP planning (THIS DEVICE only)

  
First select already-linked, active tasks in the Notion preview. Prepare baselines only for tasks whose SP plan already agrees with Notion. If a task differs, manually review and apply the change in section 4b first. Preparing baselines writes only Alf synced metadata; it does not update either app.

  
After separately enabling on this device, the plugin checks a small batch of the anchored tasks approximately every 10 minutes while Super Productivity and its plugin are running. Only title, estimate and execution date can be refreshed, and only if the SP plan has not been edited since the last agreed baseline. Conflicts are skipped rather than overwritten. No Notion writes, task creation or deletion, focus totals, habit updates or SuperSync controls.

  
Experimental: enable on ONE device only. Android background suspension, offline periods, rate limits and SuperSync delivery can delay or interrupt runs. Turning this off is immediate for subsequent checks, not a cancellation of a write already in progress. No distributed lock or atomic conflict resolution is available.

  
  

  

  
  

    
    
  

  





  
5. Optional actual work time → existing Notion tasks

  
This writeback changes only the mapped Actual Time Number property on each selected and linked Notion task. The original plan, deadline, status, task title, and relations remain unchanged. Parent task aggregates are skipped to prevent duplicate counting. No Pomodoro completion count is inferred from tracked time.

  

    
  

  

  
  

    
  

  





  
5b. Automatic actual work time → existing Notion Number (EXPERIMENTAL)

  
First use the manual time review/writeback above until each task's existing Notion actual-time value matches the recorded SP work time. Then select those already-linked tasks in a fresh Notion preview and explicitly prepare an exact matching baseline. Preparation writes only Alf metadata; it never changes Notion or SP tasks.

  
After enabling on this device, the plugin may export only positive, increasing, already-tracked time for those anchored individual tasks, at most 5 per periodic check. It rechecks the existing Notion property ID, original task and database, exact prior Notion number, SP time and synced link before any PATCH. A higher or manually changed Notion value stops that task. No new Notion pages, properties or databases; no completed Pomodoro calculations.

  
This writes to Notion without another prompt after opt-in. Experimental: enable on only ONE device, only against disposable test data. Android suspension, network retries, Notion rate limits and non-atomic PATCH may affect it; unknown outcomes require manually reconciling/reseeding. This feature is independent from planning auto-pull and is OFF by default.

  
  

  

  
  

    
    
  

  





  
6. Observed focus sessions (read-only report)

  
Alf records only future focus-session starts and completions observed while the plugin is active. Unknown mode/task, interrupted, or ambiguous sessions are excluded. A verified automatic Pomodoro completion counts once by session ID; manually ended sessions do not count as completed Pomodoros. Historical sessions cannot be backfilled. This report does not write anything to Notion.

  

  

  
Optional writeback: observed Pomodoros lower bound ONLY

  
Never use your official Completed Pomodoros field here. Map a separate existing Number property explicitly labeled as a partial observed minimum above. This observer misses historical/offline/background sessions. Only verified automatic Pomodoro completions already recorded by the active plugin qualify; counts are cumulative per SP task, not daily. No missing Notion field or database is created.

  
First pin stable task property IDs and preview matching Notion tasks; select rows above. A separate review and authorization is needed on every attempt. The value only increases, and writeback refuses missing/ambiguous links, stale observation snapshots, changed Notion properties, or more than 2,000 observer records.

  

  

  
  

  





  
7. Notion habit definitions ↔ existing SP Habit Tracker

  
Read your existing Notion habit definitions and show Super Productivity's existing habit counters. Link a Notion habit to an existing SP counter by exact IDs. This does not create a Notion database, a habit, an occurrence, or a counter. Habit-day sync remains a separate development step.

  

    
    
  

  

    
    
  

  
Alf suggests a counter only when the existing Notion habit title and the SP counter title match exactly after safe whitespace/case normalization, and the match is unique on both sides. Suggestions are not saved until you explicitly approve the mapping. Other habits stay unlinked.

  
Pin existing Notion property IDs before renaming habit fields. Pins are saved only in Alf's synced mapping metadata, never in Notion. Habit-day numeric writeback now requires the occurrence count field to be pinned.

8. Existing habit-day occurrences → Notion (manual, opt-in)

  
Use today's Super Productivity logical day and existing Notion habit occurrence pages in your configured task/board source. Alf updates only an existing numeric completion/count property; it never creates daily rows, habit definitions, or databases. Start with test data.

  

    
    
    
    
    
    
  

  

  

  
  

  





  
8b. Automatic existing habit-day counts → Notion (EXPERIMENTAL, one device)

  
This is a separate, OFF-by-default opt-in. Link the existing Notion habit definitions to their intended SP SimpleCounters, pin all four existing occurrence IDs, then preview today's existing habit-day records. Automatic writes are allowed only for individual habit definitions explicitly approved from that preview, including their future logical days when a corresponding existing Notion occurrence already exists. No new pages, definitions, properties or counters are created.

  
Consent policy: an existing Notion habit-day Number that is blank or zero may be filled from a positive, compatible SP counter on the same day. An already matching positive count may be anchored without a write. A nonzero Notion value that disagrees before any anchor, or any subsequent manual Notion edit or SP counter reset, is a conflict and is skipped. Duplicate habit/day records and ambiguous counter mappings are refused.

  
Automatic Notion Number PATCHes occur without further approval once enabled. Enable only on ONE disposable test device, not production. This isn't a guaranteed Android background service, no new day rows are created, and Notion has no atomic cross-device compare-and-swap.

  
  

    
    
  

  

  
Every approval replaces the complete set of permitted habits on THIS device; older synced approval history cannot add them back. Disable clears the local writer flag and this device's grant list. To authorize a different set, preview the current existing day and opt in again; the earlier set will no longer write.





  
8c. Mark an existing daily habit Done — reviewed Status only

  
For boards without a separate habit-count Number, you can review a positive SP SimpleCounter against an existing Notion habit-day page, then explicitly mark its existing Status as completed. A positive count is not proof that a habit target was reached: review each proposed change first. No numeric count, work time, relation, new page or counter is written. This is a manual action only, never background automation.

  

    
    
  

  
Uses the task Status mapping above and the pinned habit occurrence type, relation and date fields; no habit numeric field required. Link definitions to counters first and pin task Status plus the three occurrence property IDs.

  

  

  
  

  





  
9. Automatic synchronization diagnostics (THIS DEVICE)

  
Read-only local diagnostics for the three optional engines: Notion → SP planning, SP → Notion actual time and SP → existing Notion habit-day counts. These status records contain only time and counters: no Notion token, task names or page IDs. They stay local and are not copied by SuperSync.

  

  

  
Successful code execution does not confirm a second device has received SuperSync data. A conflict/error count indicates affected records were skipped, not silently overwritten. Android background sleep and Notion rate limits may mean no recent check at all.
